# 1. Функциональные модули

Принцип: модуль = ограниченный контекст со своими таблицами, сервисами, контрактом API и (для фронта) набором экранов. Модули общаются через публичные сервисы и доменные события, не через чужие таблицы.

## 1.1. Backend-модули (`apps/api/src/modules/*`)

| # | Модуль | Ответственность | Роли |
|---|---|---|---|
| M01 | `identity` | Аутентификация через MAX, JWT-сессии, пользователи, роли, переключение активной роли, профили (student/parent/teacher), настройки пользователя (тема, язык), код привязки ученика | все |
| M02 | `school` | Школа, часовой пояс, политики (показ контактов преподавателя), код приглашения преподавателей; место для 4-й роли | admin (позже) |
| M03 | `catalog` | Кружки: описание, категория, стоимость, обложка, теги; выдача каталога для онбординга и родителя; карточка преподавателя | student, parent |
| M04 | `groups` (+`schedule`) | Группы внутри кружка, преподаватель группы, зачисление (Enrollment), правила расписания, генерация занятий, календарные выборки, отмена/перенос | все |
| M05 | `attendance` | Отметка посещаемости по занятию, статусы, история | teacher (запись), student/parent (чтение) |
| M06 | `courses` | Структура курса (модули → блоки), типы контента, черновик/публикация; чтение курса учеником; прогресс по блокам и курсу | teacher, student |
| M07 | `assignments` | Задания (простые и привязанные к блокам курса), сдачи, попытки, автопроверка тестов, ручная проверка, дедлайны/просрочки | teacher, student |
| M08 | `analytics` | Лента событий активности, дневные агрегаты, единые формулы метрик, динамика за период, «требуют внимания», агрегирующие дашборды всех ролей | все (чтение) |
| M09 | `ai` | Шлюз к GigaChat, сборка учебного контекста ученика, диалоги (онбординг, тьютор), кэш инсайтов (комментарии/резюме), персональная траектория | все |
| M10 | `course-builder` | Загрузка материалов → пайплайн (extract → outline → generate → assemble) → черновик → ревью преподавателя → создание курса | teacher |
| M11 | `files` | S3-хранилище, presigned upload, метаданные файлов, доступ к медиа, извлечение текста | все |
| M12 | `family` | Привязка родитель↔ребёнок, список детей, проверка доступа родителя к данным ребёнка | parent |
| M13 | `payments` | Стоимость, оплаченные периоды, создание платежа через провайдера, вебхуки, история | parent |
| M14 | `notifications` | In-app уведомления, настройки уведомлений, напоминания (worker), push через MAX (позже) | все |
| M15 | `support` | Обращения в поддержку | все |

## 1.2. Frontend-фичи (`apps/web/src/pages/*`)

Разделение по ролям на уровне страниц, общие сущности — в `entities/`.

### Ученик
- `student/home` — сегодня/ближайшие занятия, календарь, задачи, краткая аналитика, ИИ-комментарий.
- `student/tutor` — чат с ИИ-тьютором (стриминг).
- `student/courses` — список курсов, структура курса, просмотр блоков всех типов, сдача заданий, список заданий.
- `student/settings` — тема, язык, уведомления, поддержка.
- `student/profile` — профиль, статистика, «Моя траектория», смена роли.
- `onboarding` — диалог с ИИ, выбор кружков.

### Родитель
- `parent/children` — выбор/переключение ребёнка, привязка по коду.
- `parent/home` — занятия сегодня/ближайшие, пропуски, новые/просроченные задания, динамика, ИИ-резюме.
- `parent/analytics` — подробная аналитика за период.
- `parent/clubs` — кружки ребёнка, карточка кружка, карточка преподавателя.
- `parent/payments` — стоимость, оплаченный период, следующая оплата, история, оплата.

### Преподаватель
- `teacher/home` — занятия сегодня, группы, задания на проверку, события, аналитика.
- `teacher/groups` — группы, список учеников со статистикой, «требуют внимания».
- `teacher/student-card` — карточка ученика с аналитикой и ИИ-резюме.
- `teacher/attendance` — занятия группы, отметка посещаемости, создание/отмена занятия.
- `teacher/assignments` — создание простого задания, список, проверка сдач.
- `teacher/course-builder` — загрузка материалов, прогресс генерации, редактор черновика/курса, публикация.

### Общие
- `auth` — вход через MAX, выбор роли, dev-вход.
- `notifications` — центр уведомлений.

## 1.3. Вне MVP (зафиксировано, чтобы не расползаться)
- Экраны 4-й роли.
- Импорт учеников из внешних систем.
- Интерактивные блоки сложнее flashcards / matching / fill-gaps.
- OCR рукописных материалов.
- Возвраты платежей, рассрочка.
- Реалтайм (websocket): используем refetch + SSE только для ИИ-стриминга.
- Версионирование опубликованных курсов (в MVP структура после публикации заморожена).
