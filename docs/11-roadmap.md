# 11. Порядок реализации

## Фаза 0 — Фундамент (волна 0, последовательно, один владелец)
F1 → F2 → (F3 ∥ F4) → (F5 ∥ F6 ∥ F7 ∥ F8).

Критерий выхода: три пустые роли открываются в браузере в mock-режиме; `POST /auth/dev` + `GET /me` работают на реальном API с seed-данными; CI зелёный; `OWNERS.yaml` заполнен под волну 1.

## Фаза 1 — Домен + экраны (волна 1, максимальный параллелизм)
- Backend: B1, B2, B7 стартуют первыми. B3, B4, B5, B8, B9 — как только B2 опубликовал сигнатуры сервисов (можно с заглушками). B6, B10 — последними (им нужны read-сервисы).
- Frontend: W1–W11 одновременно, против моков.

Критерий выхода: каждый BE-модуль покрыт интеграционными тестами по своим контрактам; каждый FE-экран работает на фикстурах во всех состояниях.

## Фаза 2 — Интеграция по ролям (I1)
Порядок: **преподаватель** (создаёт данные: посещаемость, задания, курс) → **ученик** (потребляет) → **родитель** (читает агрегаты и платит через Fake-провайдер). Seed позволяет проверять ученика и родителя до готовности преподавательских экранов.

Критерий выхода: F2, F3, F6, F7, F9, F10 (на Fake) из `07-user-flows.md` проходят end-to-end на реальном API без ИИ (ИИ-поля = `null`).

## Фаза 3 — ИИ (волна 2)
A2 (тьютор) и A3 (инсайты) первыми — они дают видимую ценность на всех трёх главных экранах. Затем A1 (онбординг) и A4 (траектория). A5 (course builder) — последним и итеративно: сначала EXTRACT + OUTLINE с ручным заполнением блоков, потом GENERATE.

Критерий выхода: F1, F4, F5, F8 проходят на реальном GigaChat; стоимость запросов на пользователя в сутки измерена и лимиты выставлены.

## Фаза 4 — Платформа и закалка (I2–I7)
MAX Bridge на реальных устройствах, платёжный провайдер на стейдже, e2e, производительность, безопасность, push.

## Фаза 5 — Расширения
4-я роль, импорт учеников, версии курсов, переиспользование курсов между группами, продвинутые интерактивы, OCR.

## Что делать, если что-то блокирует
- Нет ответа от MAX по API — не блокирует: `DevAuthProvider` и mock bridge закрывают всё до фазы 4.
- Нет доступа к GigaChat — не блокирует: `FakeLlmProvider`; A-задачи пишутся и тестируются на нём, промпты отлаживаются позже.
- Нет платёжного провайдера — `FakePaymentProvider` с ручным «успех/провал» в dev.
- Нет ответа по 4-й роли — `SCHOOL_ADMIN` в enum, `School.inviteCode` и `settings` уже есть; экраны не делаем.
