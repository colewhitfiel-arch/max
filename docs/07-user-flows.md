# 7. Основные user flows

Формат: шаги пользователя → что делает система (модули, события). Эти сценарии — основа e2e-тестов (I3).

## F1. Первый вход ученика + онбординг
1. MAX открывает мини-апп → `POST /auth/max` → пользователь новый: `roles=[]`, `needsRoleSetup=true`.
2. Экран выбора роли → «Я ученик» → `POST /auth/roles {STUDENT, inviteCode?}` → `StudentProfile`, JWT с `activeRole=STUDENT`.
3. `student.onboardingCompleted=false` → редирект `/onboarding`. Гейт стоит не только на `/`: `StudentShell` уводит на `/onboarding` с любого `/student/*` (прямой заход, deep-link, переключение на роль STUDENT), а сам `/onboarding` открыт только активной роли STUDENT (остальных уводит на главную их роли). `POST /student/onboarding/start` → ИИ задаёт первый вопрос; сбой старта — ошибка с «Повторить». Незавершённое знакомство (обновили страницу, вернулись позже) продолжается: `/start` отдаёт ту же ленту (`history`), кнопки кружков последней реплики и, если профиль уже собран, `profileDraft` — сразу экран выбора кружков.
4. Диалог 5–8 реплик (интересы, предметы, навыки, цели, время, форматы), ответы стримятся; каждое новое сообщение (приветствие, ответ ученика, реплика тьютора) появляется плавно (`ChatBubble appear`, без анимации при `prefers-reduced-motion`). Если тьютор предлагает кружки — под репликой кнопки (`done.clubOptions`): одно нажатие отправляет название кружка ответом, без ручного ввода; выбранный так кружок на экране выбора уже отмечен «Записаться» (не попал в подборку — стоит первым с причиной «выбрал в разговоре»). Отметка ставится, только когда ответ принят: не ушёл (ошибка стрима) — кружок не отмечен. Отметки живут в клиенте и после обновления страницы не восстанавливаются. Когда профиль полный — `done.isComplete=true` + `profileDraft`. В mock-режиме (MSW и `AI_PROVIDER=mock`) вопросы детерминированные: интересы (в `/start`) → цели (с кружками школы кнопками) → часы в неделю и формат → «что хочется попробовать попозже» (из этого ответа — `futureInterests`); 4-й ответ завершает диалог.
5. `GET /student/onboarding/recommendations` → 3–5 кружков с причинами (ИИ ранжирует каталог школы по профилю; без школы — весь каталог).
6. Выбор кружков → `POST /student/onboarding/complete` → профиль обновлён, `Enrollment` созданы, события `enrollment.created`, `student.profile.updated`.
7. Редирект `/student/home`.

## F2. Ученик: главная → выполнить задание
1. Главная ученика помещается в экран без вертикального скролла (`Screen fit`): иллюстрации предметов занимают оставшуюся высоту и уменьшаются, а если занятий дня больше, чем влезает, прокручивается только таблица расписания (`DaySchedule fit`). `GET /student/home` — сегодня/ближайшие, задачи, статистика, ИИ-комментарий (из кэша `AiInsight`, может быть `null`), серия и кристаллы (docs/04 §4.6). Экран: огонёк/кристаллы, дуга «Посещения», иконки предметов выбранного дня (свободный день — все кружки серыми), «‹ Сегодня ›» с расписанием (виджет `DaySchedule`, общий для ученика, родителя и преподавателя: стрелка «назад» заблокирована только на сегодняшнем дне — прошедший день, выбранный в календаре, листается в обе стороны; отменённое занятие остаётся в списке приглушённым с бейджем «Отменено» и не подсвечивается как текущее; сбой загрузки дня вне окна главной — ошибка с «Повторить», а не «занятий нет»). Иконка календаря открывает шторку с месяцем (`GET /student/calendar?from&to`, точки на днях с занятиями) и занятиями выбранного дня; выбор дня переключает и расписание. Колокольчик (жёлтый с числом, если есть непрочитанные) открывает боковую панель уведомлений (`GET /notifications`, `POST /notifications/read`).
2. Тап по заданию → `GET /student/assignments/:id`. Если задание из блока курса — кнопка «Открыть в курсе».
3. Сдача: текст/файлы (`POST /files/upload-url` → PUT в S3 → `POST /files/:id/confirm`) → `POST /student/assignments/:id/submit` с `Idempotency-Key`.
4. Система: `Submission(SUBMITTED, isLate)`; для QUIZ — автопроверка → `GRADED`. События `submission.submitted` (+ `submission.graded`).
5. Обработчики: `analytics` пересчитывает день; `notifications` → преподавателю `SUBMISSION_RECEIVED`; `ai` помечает инсайты ученика устаревшими.
6. Преподаватель видит сдачу в «на проверку», родитель — в динамике, тьютор — в контексте следующего сообщения.

## F3. Ученик: прохождение курса
1. `/student/courses` → карточка с прогрессом и «следующий блок». Экран курса `/student/courses/:id`: карточка «Пройдено N из M» с кнопкой «Начать курс» / «Продолжить: <шаг>» (первый непройденный блок), модули и блоки с отметками; все шаги пройдены — «Курс пройден!».
2. Шаг курса `/student/blocks/:id` — плеер (`widgets/course-player`): модуль, «Шаг N из M» и прогресс курса сверху, «Назад» / «Дальше» снизу. Открытие → `POST /student/blocks/:id/open` → `BlockProgress(OPENED)`, событие `block.opened`. TEXT-блок показывается как Markdown (`@edu/ui` `Markdown`: заголовки, выделение, списки, код; сырой HTML — текстом, ссылки только http(s) — через MaxBridge), а не исходным текстом с «#» и «**».
3. Материал (TEXT, VIDEO, INTERACTIVE, ДЗ без сдачи) засчитывается кнопкой «Дальше» → `POST /student/blocks/:id/complete` → `BlockProgress(COMPLETED)`, `CourseProgress` пересчитан синхронно в `courses`, событие `block.completed` → следующий шаг (после последнего — экран курса с итогом). Интерактив живой и проверяется на клиенте: карточки переворачиваются («Знаю» / «Ещё раз»), пары сопоставляются, пропуски `{{ответ}}` вписываются и проверяются (регистр и «ё» не важны, варианты через «|»).
4. Тест (QUIZ): ответы → «Проверить ответы». Блок стал заданием при публикации — ответы сдаются заданием (`POST /student/assignments/:id/submit`); модуль `courses` по событию `submission.submitted` проверяет тест сразу (`AssignmentsService.autoGrade`: доля верных → балл задания, `GRADED`, событие `submission.graded`) и засчитывает блок. Тест без задания — `complete` с ответами. Разбор попытки (`quizReview` в блоке и в ответе `complete`): балл, «пройден / нужно ≥ passScore», по каждому вопросу «верно / неверно» и выбранные варианты; правильный ответ и пояснение — только у верно отвеченных вопросов или когда попытки кончились. Не 100% — «Пройти ещё раз».
5. Вопрос, практика, ДЗ со сдачей: условие и форма сдачи прямо в плеере (текст/файлы, как F2 п.3); сдача засчитывает шаг (событие `submission.submitted` → `BlockProgress(COMPLETED)`), оценку ставит преподаватель — статус и комментарий видны в том же шаге. До сдачи «Дальше» — «Пропустить» (шаг не засчитывается).

## F4. Ученик: ИИ-тьютор
1. Чаты в духе ChatGPT. Пункт меню «ИИ-тьютор» и кнопка «Новый чат» (карандаш в шапке) открывают новый пустой чат `/student/tutor`; диалог создаётся на сервере первой отправкой (`POST /ai/conversations`), адрес сразу переходит на `/student/tutor/:conversationId` (стрим не прерывается), пустые диалоги не копятся. Кнопка слева в шапке — боковая панель «История чатов»: «Новый чат» и прошлые чаты по группам (сегодня, вчера, 7 дней, ранее; `GET /ai/conversations?kind=TUTOR`, чаты без сообщений скрыты), тап открывает старый чат, корзина удаляет (с подтверждением, `DELETE /ai/conversations/:id`). Знакомство из онбординга — чат «Знакомство с тьютором». Диалоги и сообщения хранятся в БД: после обновления страницы открыт тот же чат.
2. Лента диалога — `GET /ai/conversations/:id/messages` с конца: первая страница — последние 20 сообщений, сверху кнопка «Показать раньше» подгружает более старые (`nextCursor`).
3. Сообщение → `POST /ai/conversations/:id/messages` → сервер берёт `StudentContext` (кэш 5 мин) → системный промпт `tutor.system` (актуальная версия — `packages/ai/src/prompts`) + последние 20 сообщений → GigaChat stream → SSE.
4. Сохранение `AiMessage` (user/assistant), событие `tutor.message.sent` → `ActivityEvent` (без ответа модели событие не шлётся).
5. Ошибка стрима (лимит, сеть, сбой) не теряет вопрос: «отправленный» пузырь убирается, если ответ не начался — текст возвращается в поле ввода; лента перезапрашивается. «Стоп» до первого токена не добавляет пустой ответ; частичный ответ после «Стоп» пропадает до прихода перезапрошенной ленты. Пока новый чат создаётся (первая отправка, стрима ещё нет), вместо «Стоп» — неактивный индикатор: остановить можно только начавшийся ответ. Индикатор остаётся и после первого ответа нового чата, пока не придёт его лента с сервера: следующий вопрос можно набрать, а отправить — когда лента загрузится (иначе он разошёлся бы с ней: пустой чат или лента без второго вопроса).
6. Лимит сообщений в сутки (день по Москве, тратится только на успешный ход) → 429 с человеческим текстом в UI.

## F5. Профиль и «Моя траектория»
1. `/student/profile` → статистика, кружки, `GET /student/trajectory`. «Моя траектория» свёрнута по умолчанию; шеврон в заголовке (`aria-expanded`) раскрывает и скрывает её, «Обновить» — в раскрытом виде.
2. Траектория генерируется worker'ом: еженедельно по cron и при ≥5 значимых событиях (сдачи/оценки) с последней генерации; `sourceHash` исключает повтор на тех же данных.
3. Ручной «Обновить» → 202, job в очередь, UI показывает «Пересчитываем» и опрашивает `GET /student/trajectory` раз в 5 с до новой `generatedAt`, но не дольше 60 с (подпись «обновится через минуту»), затем снимает статус.

## F6. Преподаватель: отметить посещаемость
1. `/teacher/assignments` → кнопка «Отметить посещаемость» → `/teacher/attendance`: занятия за 14 дней назад и 7 вперёд (`GET /teacher/calendar`), разложенные по важности — «Сегодня», «Ждут отметки» (начались, но ещё `PLANNED`), «Ближайшие». Отменённые не показываются. Занятие в состоянии `DONE` помечено «Отмечено».
2. Занятие → `/teacher/attendance/:lessonId` → `GET /teacher/lessons/:id/attendance` → зачисленные ученики с текущими статусами.
3. По умолчанию все `PRESENT` (уже проставленные отметки сохраняются), преподаватель меняет только отличия — по ученику сегментированный переключатель из 4 статусов, плюс «Все пришли» / «Никого не было». Сохранение — одним `PUT /teacher/lessons/:id/attendance` со всем листом.
4. Система: upsert `Attendance`, `Lesson→DONE`, событие `attendance.marked`. Повторный `PUT` идемпотентен: лист перезаписывается целиком. Отменённое занятие отметить нельзя (422), ученик не из группы в листе — 422.
5. Обработчики: `analytics` (день каждого ученика), `notifications` (родителю `ATTENDANCE_ABSENT`, если включено), `ai` (инвалидация).

## F6a. Отметка посещаемости по QR-коду
Камеру и распознавание QR не пишем: ученик сканирует встроенным сканером MAX (`WebApp.openCodeReader`), проверку делает наш сервер.
1. Преподаватель: лист занятия (F6, шаг 2) → «QR-код для отметки» (кнопка есть только в день занятия и не у отменённого) → `/teacher/attendance/:lessonId/qr`. Экран берёт `GET /teacher/lessons/:id/attendance/qr` каждые `ATTENDANCE_QR_REFRESH_SEC` (30 с) и рисует QR (`@edu/ui` `QrCode`); ниже раз в 5 с обновляется «Отметились: N из M» с именами. «Скопировать ссылку» — для ученика без MAX.
2. Код — подпись HMAC-SHA256 `(lessonId, срок)` ключом, производным от `JWT_SECRET`; в БД не хранится, живёт `ATTENDANCE_QR_TTL_SEC` (90 с): снимок QR, пересланный отсутствующему, быстро протухает. В QR зашита ссылка: с `MAX_BOT_NAME` — диплинк `https://max.ru/<бот>?startapp=checkin_<код>` (обычная камера телефона откроет мини-приложение сразу на отметке), без него — `${WEB_URL}/check-in/<код>`. Код выдаётся только своему преподавателю (чужое — 403), только в день занятия в поясе школы и не для отменённого (422).
3. Ученик: на главной, пока сегодня есть неотменённое занятие без отметки «был»/«опоздал», — «Отметиться по QR». В MAX открывается сканер (только камера, без выбора снимка из галереи); вне MAX — поле для ссылки из QR. Код из ссылки (`parseAttendanceQrValue`) → `/check-in/:code` (туда же ведёт диплинк `startapp=checkin_<код>`) → `POST /student/attendance/check-in { code }`.
4. Сервер проверяет подпись и срок, что занятие есть и не отменено, что ученик в составе группы (ACTIVE). Отказ — 422 с `details.reason`: `CODE_INVALID`, `CODE_EXPIRED`, `LESSON_CANCELLED`, `NOT_ENROLLED`; экран показывает причину и «Сканировать снова» (для битого/протухшего кода).
5. Успех: `Attendance` ученика → `PRESENT` (отметкой преподавателя группы; комментарий не трогается), `Lesson→DONE`, событие `attendance.marked` с одной строкой — дальше как в F6, шаг 5. Уже «был»/«опоздал» — ничего не меняется (`alreadyMarked: true`); «не был»/«уважительная» перезаписывается: ученик отсканировал живой код, значит, он на занятии. Экран: «Отметка поставлена», кружок и время занятия.
6. Преподаватель на экране кода → «Завершить и отметить остальных» → лист, где неотсканировавшие по умолчанию «Не был» (а не «Был», как без QR) → «Сохранить» (F6, шаг 3–4).

## F7. Преподаватель: простое задание
1. `POST /teacher/assignments {publish:true}` — группа, текст, дедлайн и (необязательно) `studentIds`. Отдельного экрана у простого задания нет: с экрана заданий преподаватель идёт в мастер «Задать ДЗ» (F8), а эта ручка остаётся для заданий без учебного содержимого.
2. `notifications` → ученикам группы `ASSIGNMENT_NEW`; задание появляется в `/student/home` и у родителя в «новые задания».
3. Проверка: `GET /teacher/assignments/:id/submissions` → сдача → `POST /teacher/submissions/:id/grade` → событие `submission.graded` → уведомления ученику/родителю, аналитика.

## F8. Преподаватель: задать ДЗ / собрать курс (course builder)
Входы — кнопка «Задать ДЗ» на `/teacher/assignments` (мастер ниже), «Создать курс из конспекта» на `/teacher/courses` и «Курс из конспекта» в «Первых шагах» главной (оба ведут на конструктор `/teacher/course-builder`). Ученик в любом случае видит курс, который просто пополняется.

Конструктор `/teacher/course-builder`: по умолчанию «Из конспекта» — «Выбрать файлы» (pdf/docx/txt/md; MIME по расширению, если браузер его не знает) или «Взять пример конспекта» (готовый Markdown-конспект про датчик HC-SR04 грузится тем же путём, что и файл с диска); единственная группа выбирается сама, групп нет — «Создать группу». Вкладка «По теме» — ИИ сам пишет конспект.

1. `/teacher/assignments/new`, три шага:
   - **Кому** — группа (`GET /teacher/groups`), затем «Всей группе» (по умолчанию) или выбор учеников галочками (`GET /teacher/groups/:groupId`). Без группы и без хотя бы одного выбранного ученика дальше не пустит. Групп нет — «Создать группу» (F19); в выбранной группе нет учеников — подсказка «Добавить учеников» (к составу группы, F19).
   - Экран мастера — ровно по высоте области между шапкой и меню и сам не прокручивается: прокручивается только поле шага, «Далее»/«Назад»/«Сгенерировать» всегда видны внизу.
   - **Что** — «Одно ДЗ» (`target: HOMEWORK`, ровно один модуль) или «Целый курс» (`target: COURSE`); куда положить — «Новый курс» или существующий курс группы (`GET /teacher/courses?groupId`, архивные не предлагаются); срок сдачи и название.
   - **Материал** — «Описать словами» (тема/задание, ≥ 10 символов) или «Загрузить материалы» (pdf/docx/txt/md). Материалы png/jpg/pptx загрузить можно, но задачу с ними сервер отклоняет сразу (422 `BUSINESS_RULE`): текст из них пока не извлекается.
2. `POST /teacher/course-builder/jobs` → worker: EXTRACT → OUTLINE → GENERATE → ASSEMBLE; фронт опрашивает job, показывает этап и прогресс.
3. `READY` → уведомление `GENERATION_DONE` → экран ревью: модули/блоки; нажатие на блок раскрывает содержимое целиком с ответами (`entities/course` `BlockPreview`: теория, вопросы с отмеченными верными вариантами и пояснениями, эталон вопроса, карточки, пары, пропуски); `PUT .../draft` до принятия. Две кнопки: «Опубликовать для группы» (принять + опубликовать без параметров: задания всей группе без срока — ученики видят курс сразу) и «Сохранить черновиком» (только принять).
4. «Принять» → `POST .../accept`:
   - `targetCourseId` задан — новые модули дописываются в конец курса, курс остаётся тем же (ученик продолжает проходить его же);
   - иначе создаётся `Course(DRAFT)`;
   - `target=HOMEWORK` (а также дополнение уже опубликованного курса) публикуется сразу: блоки-задания модуля становятся `Assignment` с `dueAt` и `studentIds` задачи. Целый новый курс остаётся `DRAFT` — его преподаватель публикует сам.
5. «Опубликовать» → дедлайны для блоков-заданий → `POST /teacher/courses/:id/publish`. Публикация идемпотентна и инкрементальна: блок, у которого задание уже есть, пропускается, поэтому курс можно дополнять сколько угодно раз. Экран курса `/teacher/courses/:id`: черновик — «Опубликовать для группы»; опубликованный — «Прогресс учеников» (`GET /teacher/courses/:id/progress`: процент, последняя активность; пустая группа — «Открыть группу») и «Убрать в архив» (`POST .../archive`, курс пропадает у учеников); блоки раскрываются, как на ревью. Архивные курсы в списке `/teacher/courses` — отдельным разделом «Архив» внизу.
6. Событие `course.published` → `notifications` → ученикам `COURSE_PUBLISHED`.

## F9. Родитель: привязка ребёнка и просмотр
1. Вход → роль PARENT → главная `/parent`: детей нет — в карусели «сердечек» только белый «+» → «Добавить ребёнка»: ссылка-приглашение (F14) или код из профиля ребёнка → `POST /parent/children/link`. «+» есть всегда (добавить ещё ребёнка; экран детей, выбор ребёнка в аналитике).
2. Выбор ребёнка — свайп карусели сердечек (Zustand `selectedChildId`, персистится в MAX storage) → `GET /parent/children/:id/home` (расписание как у ученика: «‹ Сегодня ›», календарь, уведомления) и `GET /parent/children/:id/homework-progress?days=1|7|30` (кружки «Выполненные задания»: чем больше сделано из рекомендованного, тем кружок меньше; формула — docs/04 §4.6).
3. Аналитика `/parent/analytics` → выбор ребёнка → `GET /parent/children/:id/analytics`: «Посещения» (дуга недели), «Домашние задачи» (правильно / неправильно / предстоят), по кружкам — полоса итогов и «Подробнее» → сетка заданий (зелёный — сделано, красный — дедлайн прошёл или < 30%, жёлтый — дедлайн ≤ 72 ч, серый — не скоро). Тап по клетке → `GET /parent/children/:id/groups/:groupId/tasks` — условия, код, ответ ребёнка и правильный ответ.
4. Переключение ребёнка → все запросы перезапрашиваются по новому `studentId` (ключи Query содержат `studentId`).
5. Статус связи: на главной (сердца), в выборе ребёнка аналитики и при авто-выборе (`ParentShell`) участвуют только дети со связью `ACTIVE`; выбранный не-ACTIVE ребёнок сбрасывается на первого ACTIVE (или ни на кого). Если детей со связью `ACTIVE` нет (только `PENDING`/`REVOKED`), экраны «про ребёнка» показывают пустое состояние «Добавить ребёнка». На экране «Дети» (`/parent/children`) у `PENDING`/`REVOKED` — бейдж статуса («Ожидает»/«Отвязан») и нет кнопки «Выбрать», у выбранного — бейдж «Выбран». Неверный код привязки — «Код не найден…» (NOT_FOUND), а не «раздел в разработке».
6. «Дети», «Кружки» и «Оплата» открываются и из настроек родителя; «Назад» на них — по истории, по прямой ссылке — на `/parent`.
7. Настройки родителя `/parent/settings`: профиль, «Семья и оплата» (дети, кошелёк, оплата, кружки), внешний вид (только тема), аккаунт (роль, поддержка — чат в MAX из `VITE_SUPPORT_URL`, как у ученика), выход. Уведомлений, выбора языка и подписи о приложении у родителя нет.
8. Размеры экранов: главная `/parent` фиксирована ровно в окно — шапка и сердца стоят, кривая панели заходит под подпись выбранного сердца (как в макете), а расписание и «Выполненные задания» прокручиваются внутри панели, только если не влезли (в MAX окно ниже браузерного). Тьютор — шапка и чат ровно в высоту окна, прокручивается только длинная лента. Экраны-списки (настройки, дети, кружки, оплата, профиль, аналитика) прокручиваются по содержимому.

## F10. Родитель: оплата
1. `/parent/payments` → кружок → «Оплатить» → количество месяцев → `POST /parent/children/:id/payments` с `Idempotency-Key` (один ключ на попытку оплаты периода: повтор после сбоя — тот же ключ) → `confirmationUrl`. Спиннер — только на нажатой кнопке «Оплатить».
2. Открытие платёжной страницы через `MaxBridge.openLink`.
3. Провайдер → `POST /webhooks/payments/:provider` → подпись → `Payment(SUCCEEDED)` → `PaidPeriod` → событие `payment.succeeded` → уведомление родителю.
4. После «Оплатить» экран опрашивает `GET /parent/payments/:id` раз в 3 с, пока статус `PENDING`, но не дольше 60 с; затем показывает тост с итогом и перезапрашивает платежи ребёнка (история, «оплачено до»). Даты `paidUntil`/`nextPaymentAt` (`YYYY-MM-DD`) показываются как локальные (`formatDateOnly`), без сдвига часового пояса.

## F11. Переключение ролей

Добавить роль — `POST /auth/roles`. Прежний refresh-токен при смене роли не отзывается (техдолг, docs/12).

## F14. Родитель: приглашение ребёнка по ссылке
1. Родитель → «Добавить ребёнка» (главная, аналитика, тьютор) или «Дети» → «Пригласить по ссылке» → `POST /parent/children/invites` → `{ token, url, expiresAt }` (7 дней, одноразовая). `url` — диплинк мини-приложения MAX `https://max.ru/<MAX_BOT_NAME>?startapp=invite_<token>`; без `MAX_BOT_NAME` — веб-адрес `${WEB_URL}/invite/<token>` (для браузера; внутри MAX такая ссылка откроется в браузере, где входа через MAX нет).
2. «Поделиться» (`navigator.share`, иначе копирование: Clipboard API, в WebView без него — выделение поля и `execCommand('copy')`) → родитель отправляет ссылку ребёнку в MAX. Пока ссылка на экране, список детей перечитывается раз в 5 с: когда ребёнок подтвердит, родитель сразу видит тост «Ребёнок принял приглашение: …» (ребёнок, привязанный в это время по коду, за принявшего не считается), ребёнок появляется в списке (из шторки «Добавить ребёнка» — выбирается и шторка закрывается), а ссылка сбрасывается — для следующего ребёнка создаётся новая.
3. Ребёнок открывает ссылку в MAX → мессенджер запускает мини-приложение на корневом адресе со `start_param=invite_<token>` → при старте (один раз за запуск, только со стартового корня) приложение переходит на `/invite/<token>` и только после этого начинает вход (иначе редирект с `/` отменил бы переход, пока грузится экран); ждёт перехода не дольше 8 с (`START_PARAM_WAIT_MS`) — если экран приглашения не загрузился (сеть «повисла»), запуск идёт как без диплинка, а не висит на сплэше; вход — по подписи MAX, аноним после входа возвращается на приглашение. В браузере то же эмулирует `?startapp=invite_<token>` (mock-мост). Прямой адрес `/invite/<token>` тоже работает.
4. `/invite/:token` (после входа). Активная роль STUDENT → `GET /student/parent-invites/:token` → «{Родитель} хочет следить за твоими успехами» → «Подтвердить» → `POST /student/parent-invites/:token/accept` → связь `ParentStudentLink` `ACTIVE` (токен гасится в той же транзакции) → `/` (онбординг ученика, если не пройден, иначе `/student`).
   - Повтор тем же учеником идемпотентен, пока связь `ACTIVE`; после отвязки погашенная ссылка связь не восстанавливает (`BUSINESS_RULE`), нужна новая.
   - Ребёнок уже привязан к этому родителю: `GET` отдаёт `alreadyLinked: true`, экран сразу показывает «Ты уже привязан к этому родителю» без «Подтвердить»; `accept` в этом случае — 409 `CONFLICT`, ссылка не гасится (её можно отправить другому ребёнку).
   - Ссылку уже принял другой ученик — 409 `CONFLICT`, экран «Приглашение уже принято»; одновременное принятие двумя учениками привязывает ровно одного. Подсказка на этом экране — по `alreadyLinked`: связь есть — «ничего делать не нужно», нет (принял другой ученик или связь потом отвязали) — «Попроси родителя отправить новую ссылку».
   - Истёкшая — «Срок действия ссылки истёк» (`accept` — 422 `BUSINESS_RULE`); неизвестный токен — «Приглашение не найдено» (404); свой же аккаунт (роли родителя и ученика у одного пользователя) — 422.
   - Не ученик — подсказка открыть ссылку из аккаунта ребёнка (или сменить роль); новый пользователь без ролей — «Я ученик» прямо на экране приглашения.
5. Ребёнок появляется у родителя в `GET /parent/children`, в карусели сердец и в аналитике; данные ребёнка родителю открыты (policy `assertParentLinked`).

## F17. Преподаватель: кошелёк и вывод (заглушка)
1. Чип кошелька на главной или «Настройки → Кошелёк» → `/teacher/wallet` → `GET /teacher/wallet?period=day|week|month` (1 / 7 / 30 дней, по умолчанию день): баланс, график «Изменение баланса» (`history`), «Транзакции» по дням («сегодня», «вчера», дата; поступления зелёные, вывод — красная строка «Вывод»), «Вам должны» (группа, ученик, сумма, дата следующего платежа; просроченная — красная). Колонка группы в транзакциях и «Вам должны» — самая широкая: у группы без кода там название, и на 375–390px оно переносится по словам. Смена периода перезапрашивает кошелёк.
2. «Вывести» → шторка: сумма (100 ₽ … баланс) или 1000 / 3000 / 5000 / «Всё» → `POST /teacher/wallet/withdraw { amountKopecks }` с `Idempotency-Key` (один на попытку: повтор той же суммы после сбоя — с тем же ключом, новая сумма или новое открытие шторки — новый; пока запрос идёт, шторку не закрыть) → новый баланс и операция вывода, тост «демо-режим»; кошелёк перезапрашивается после любого исхода (при таймауте виден фактический баланс).
3. Ошибки: больше баланса → 422 `BUSINESS_RULE` («Недостаточно средств»), меньше минимума → 400 `VALIDATION`, тот же ключ с другой суммой → 409 `CONFLICT`. Повтор с тем же ключом и суммой не списывает второй раз.
4. «Баланс ✕»: открыт из приложения — назад, по прямой ссылке — на `/teacher`.
5. **Поступления настоящие**: оплата родителя по `payment.succeeded` создаёт операцию `INCOME` в кошельке преподавателя группы (пока на всю сумму — доли школы в модели данных нет). Заглушкой остаётся вывод: сумма списывается с баланса, но никуда не уходит, поэтому ручка работает только при `PAYMENT_PROVIDER=fake`, иначе 501. С провайдером вывод станет выплатой со статусом (модель — docs/04, payments).

Открывается сразу после выбора роли преподавателя (после сохранения — на `/teacher`), с главной — карточка «Расскажите, что вы ведёте», пока кружки не выбраны, — из профиля («Мои кружки» → «Изменить») и настроек («Работа → Мои кружки»).
2. «Настройки → Группы» → `/teacher/groups` → «Создать группу» (или пустые «Мои группы» в профиле) → `/teacher/groups/new`: кружок — любой из 8 (свои — первыми, первый выбран), название (пусто — название кружка), цена в месяц (целые рубли, 0 — бесплатно), описание, дни занятий (день недели, начало, конец; можно без расписания) → `POST /teacher/groups`. Вместе с группой в каталоге школы появляется её кружок, занятия по расписанию — в календаре преподавателя; название уже есть среди его групп — 409.
3. После создания — экран группы с открытой шторкой «Пригласить учеников»: ссылка `/join/:token`, «Поделиться» (`navigator.share`, иначе копирование), «Сбросить ссылку» (старая перестаёт работать). Ссылка многоразовая — одна на всю группу; на экране любой своей группы — кнопка «Пригласить учеников».
4. Ученик открывает ссылку → мини-апп → `/join/:token` (после входа). Активная роль STUDENT → `GET /student/group-invites/:token`: иконка и название кружка, кто ведёт, сколько учеников, цена, расписание → «Вступить в группу» → `POST .../join` → тост, `/` (новый ученик — на онбординг). Уже в группе — «Ты уже в этой группе»; сброшенная ссылка — «Ссылка не работает»; не ученик — подсказка открыть в аккаунте ученика, новый пользователь — «Я ученик» прямо здесь (как в F14).
5. Карточка группы `/teacher/groups/:id` → «Изменить» у учеников (у пустой группы — «Добавить учеников») → `/teacher/groups/:id/edit`: название (`PATCH /teacher/groups/:id`, кнопка «Сохранить название» — только при изменении), ученики группы с «убрать» (`DELETE /teacher/groups/:id/students/:studentId`), «Добавить учеников» — поиск по имени (`GET /teacher/groups/:id/candidates?q`: ученики школы преподавателя и его других групп) и «добавить» (`POST /teacher/groups/:id/students`). Всё сохраняется сразу; после каждого изменения данные преподавателя (главная, списки, успеваемость, мастер ДЗ) перезапрашиваются.
6. Новая группа сразу доступна в мастере «Задать ДЗ» (F8) и в простом задании (F7); ДЗ «всей группе» видят и ученики, добавленные позже (в том числе по ссылке). Убранный ученик остаётся в истории (зачисление `LEFT`), адресатом ДЗ группы его выбрать нельзя; по ссылке он может вернуться.
7. Чужая группа (403) — «Группа не найдена» с возвратом к списку групп.
8. TODO (workstream J): формат deep link MAX (`url` сейчас `${WEB_URL}/join/${token}`).

## F20. Демонстрационный режим (для жюри)
1. Кнопка «Демонстрационный режим» — первая на экране «Вход» (`/auth`: в браузере; внутри MAX — если вход по подписи не удался) и над ролями на экране выбора роли (`/auth/role` при первом входе, в режиме «Добавить роль» её нет); у аккаунта с уже выбранной ролью (внутри MAX эти экраны не показываются) — строка «Демонстрационный режим» в настройках любой роли (`AccountSettings`) и диплинк `https://max.ru/<бот>?startapp=demo` (`app/start-param.ts`: запуск с корня стартует тур до входа) → тур поверх приложения (`features/demo-tour`, компонент `Coachmark` из `@edu/ui`): экран затемнён, функция подсвечена, рядом карточка «раздел · заголовок · текст · Назад / N из M / Далее · ✕».
2. Сначала — раздел «Конспект → курс» (главный сценарий, всё по-настоящему через API): Мария на конструкторе курса → тур загружает пример конспекта (`features/upload-file` `sampleMaterialFile`: upload-url → PUT → confirm) и запускает генерацию для группы «Робототехника, группа А» → экран задачи с живым прогрессом (стадия и % прямо в карточке тура; когда ИИ дописал черновик, тур переходит дальше сам) → черновик (блоки раскрываются с ответами) → тур принимает и публикует курс (прошлые демо-курсы с тем же названием — в архив, чтобы на общем стенде не копились) → Алексей видит курс → плеер → тест с мгновенной проверкой → прогресс учеников у Марии. Созданное в прогоне (`jobId`, `courseId`, шаги курса) — в контексте тура (`sessionStorage`), «Назад/Далее» и перезагрузка ничего не создают повторно; новый запуск тура — новый прогон. Сбой загрузки или генерации — тост «Не удалось выполнить шаг демо» с причиной, тур закрывается.
3. Дальше шаги идут по ролям: приветствие (с него — сразу к разделу «Конспект → курс», ученику, родителю или преподавателю) → ученик (онбординг с ИИ — Даша, дальше Алексей: главная, тьютор, задания, курс, сдача, профиль и траектория, настройки) → родитель (Ольга: дети, расписание и задания ребёнка, кошелёк, кружки, оплата, успеваемость, тьютор, привязка, каталог кружков) → преподаватель (Мария: главная, задания, «Задать ДЗ», посещаемость, успеваемость и ученик, кошелёк, группы, курсы, спрос на кружки) → итог.
4. Шаг сам входит нужным демо-пользователем (`POST /auth/dev`, только демо-пользователи в их ролях — так пускает и стенд с `AUTH_PROVIDER=max`), открывает экран и ждёт подсвечиваемый элемент (`data-tour` на экране, до 8 с; не дождался — карточка по центру без подсветки). Подсвеченное можно потрогать (написать тьютору, раскрыть карточку); остальной экран закрыт.
5. «Далее» / «Назад», стрелки ← →. «Готово» на последнем шаге — выход из демо-аккаунта (`POST /auth/logout`) и возврат к началу: внутри MAX автовход по подписи снова ведёт к выбору роли (у нового пользователя ролей нет), в браузере — экран «Вход». Escape или ✕ — закрыть тур раньше: приложение остаётся открытым в роли текущего демо-пользователя (вернуться — «Выйти из аккаунта»). Шаг хранится в `sessionStorage`: перезагрузка продолжает тур. В production (`APP_ENV=production`) демо-вход запрещён — тур закрывается с ошибкой.

## F21. Регистрация вне MAX и полный сценарий нового аккаунта
1. Экран «Вход» в браузере (`/auth`, вне MAX) — три вкладки (`?tab=login|register|demo`, ссылкой можно делиться сразу на регистрацию): «Вход» — логин и пароль (`POST /auth/login`), «Регистрация» — имя, фамилия (необязательно), логин, пароль и повтор (`POST /auth/register`), «Демо» — демо-аккаунты (`POST /auth/dev`). Внутри MAX вход по-прежнему автоматический по подписи (F1).
2. Логин — 3–32 символа (латиница, цифры, точка, дефис, подчёркивание), регистр не важен (хранится в нижнем); пароль — от 8 символов, хранится только хэш scrypt (`user_credentials`). Занятый логин — 409 «Этот логин уже занят»; неверный логин или пароль — 401 с одним и тем же текстом (не выдаём, существует ли логин). Вход и регистрация — под лимитом частоты `auth` (с одного IP).
3. Новый аккаунт — без ролей → `/auth/role` (F1): под каждой ролью — что она даёт. Ученик → знакомство с ИИ-тьютором (F1) → главная; родитель → главная и привязка ребёнка по коду или ссылке (F9, F14); преподаватель → «Что вы ведёте?» (F19) → главная с карточкой «Первые шаги» (пока нет групп): «Создать группу» и «Курс из конспекта». Код школы для преподавателя вне production необязателен — без него аккаунт попадает в демо-школу.
4. Ссылка-приглашение в группу (`/join/:token`) у анонима ведёт на вход с возвратом: регистрация → обратно на приглашение → «Я ученик» → «Вступить в группу» → знакомство → курсы группы.
5. Сквозной сценарий (проверен интеграционным тестом `apps/api/test/integration/full-scenario.test.ts` и вручную): преподаватель регистрируется → группа и ссылка → конструктор курса «Из конспекта» (свой файл или «Взять пример конспекта») → черновик → «Опубликовать для группы» → ученик регистрируется по ссылке → проходит курс в плеере, тест проверяется сразу → преподаватель видит прогресс ученика на экране курса («Прогресс учеников») и сдачи на проверку в «Заданиях».
6. В настройках у аккаунта с паролем под именем — `@логин` (`MeDto.login`).
