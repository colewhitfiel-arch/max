# 7. Основные user flows

Формат: шаги пользователя → что делает система (модули, события). Эти сценарии — основа e2e-тестов (I3).

## F1. Первый вход ученика + онбординг
1. MAX открывает мини-апп → `POST /auth/max` → пользователь новый: `roles=[]`, `needsRoleSetup=true`.
2. Экран выбора роли → «Я ученик» → `POST /auth/roles {STUDENT, inviteCode?}` → `StudentProfile`, JWT с `activeRole=STUDENT`.
3. `student.onboardingCompleted=false` → редирект `/onboarding`. Гейт стоит не только на `/`: `StudentShell` уводит на `/onboarding` с любого `/student/*` (прямой заход, deep-link, переключение на роль STUDENT), а сам `/onboarding` открыт только активной роли STUDENT (остальных уводит на главную их роли). `POST /student/onboarding/start` → ИИ задаёт первый вопрос; сбой старта — ошибка с «Повторить». Незавершённое знакомство (обновили страницу, вернулись позже) продолжается: `/start` отдаёт ту же ленту (`history`), кнопки кружков последней реплики и, если профиль уже собран, `profileDraft` — сразу экран выбора кружков.
4. Диалог 5–8 реплик (интересы, предметы, навыки, цели, время, форматы), ответы стримятся; каждое новое сообщение (приветствие, ответ ученика, реплика тьютора) появляется плавно (`ChatBubble appear`, без анимации при `prefers-reduced-motion`). Если тьютор предлагает кружки — под репликой кнопки (`done.clubOptions`): одно нажатие отправляет название кружка ответом, без ручного ввода; выбранный так кружок на экране выбора уже отмечен «Записаться» (не попал в подборку — стоит первым с причиной «выбрал в разговоре»). Когда профиль полный — `done.isComplete=true` + `profileDraft`. В mock-режиме (MSW и `AI_PROVIDER=mock`) вопросы детерминированные: интересы (в `/start`) → цели (с кружками школы кнопками) → часы в неделю и формат → «что хочется попробовать попозже» (из этого ответа — `futureInterests`); 4-й ответ завершает диалог.
5. `GET /student/onboarding/recommendations` → 3–5 кружков с причинами (ИИ ранжирует каталог школы по профилю; без школы — весь каталог).
6. Выбор кружков → `POST /student/onboarding/complete` → профиль обновлён, `Enrollment` созданы, события `enrollment.created`, `student.profile.updated`.
7. Редирект `/student/home`.

## F2. Ученик: главная → выполнить задание
1. Главная ученика помещается в экран без вертикального скролла (`Screen fit`): иллюстрации предметов занимают оставшуюся высоту и уменьшаются, а если занятий дня больше, чем влезает, прокручивается только таблица расписания (`DaySchedule fit`). `GET /student/home` — сегодня/ближайшие, задачи, статистика, ИИ-комментарий (из кэша `AiInsight`, может быть `null`), серия и кристаллы (docs/04 §4.6). Экран: огонёк/кристаллы, дуга «Посещения», иконки предметов выбранного дня (свободный день — все кружки серыми), «‹ Сегодня ›» с расписанием (виджет `DaySchedule`, общий для ученика, родителя и преподавателя: стрелка «назад» заблокирована только на сегодняшнем дне — прошедший день, выбранный в календаре, листается в обе стороны; отменённое занятие остаётся в списке приглушённым с бейджем «Отменено» и не подсвечивается как текущее; сбой загрузки дня вне окна главной — ошибка с «Повторить», а не «занятий нет»). Иконка календаря открывает шторку с месяцем (`GET /student/calendar?from&to`, точки на днях с занятиями) и занятиями выбранного дня; выбор дня переключает и расписание. Колокольчик (жёлтый с числом, если есть непрочитанные) открывает боковую панель уведомлений (`GET /notifications`, `POST /notifications/read`).
2. Тап по заданию → `GET /student/assignments/:id`. Если задание из блока курса — кнопка «Открыть в курсе».
3. Сдача: текст/файлы (`POST /files/upload-url` → PUT в S3 → `POST /files/:id/confirm`) → `POST /student/assignments/:id/submit` с `Idempotency-Key`.
4. Система: `Submission(SUBMITTED, isLate)`; для QUIZ — автопроверка → `GRADED`. События `submission.submitted` (+ `submission.graded`).
5. Обработчики: `analytics` пересчитывает день; `notifications` → преподавателю `SUBMISSION_RECEIVED`; `ai` помечает инсайты ученика устаревшими.
6. Преподаватель видит сдачу в «на проверку», родитель — в динамике, тьютор — в контексте следующего сообщения.

## F3. Ученик: прохождение курса
1. `/student/courses` → карточка с прогрессом и «следующий блок».
2. Открытие блока → `POST /student/blocks/:id/open` → `BlockProgress(OPENED)`, событие `block.opened`. TEXT-блок показывается как Markdown (`@edu/ui` `Markdown`: заголовки, выделение, списки, код; сырой HTML — текстом, ссылки только http(s) — через MaxBridge), а не исходным текстом с «#» и «**».
3. Просмотр/ответ → `POST /student/blocks/:id/complete` → `BlockProgress(COMPLETED)`, `CourseProgress` пересчитан синхронно в `courses`, событие `block.completed`.
4. Если блок — задание (QUIZ/QUESTION/PRACTICE/HOMEWORK), `complete` делегирует в `AssignmentsService.submitFromBlock` → дальше как F2 п.4–6.

## F4. Ученик: ИИ-тьютор
1. Чаты в духе ChatGPT. Пункт меню «ИИ-тьютор» и кнопка «Новый чат» (карандаш в шапке) открывают новый пустой чат `/student/tutor`; диалог создаётся на сервере первой отправкой (`POST /ai/conversations`), адрес сразу переходит на `/student/tutor/:conversationId` (стрим не прерывается), пустые диалоги не копятся. Кнопка слева в шапке — боковая панель «История чатов»: «Новый чат» и прошлые чаты по группам (сегодня, вчера, 7 дней, ранее; `GET /ai/conversations?kind=TUTOR`, чаты без сообщений скрыты), тап открывает старый чат, корзина удаляет (с подтверждением, `DELETE /ai/conversations/:id`). Знакомство из онбординга — чат «Знакомство с тьютором». Диалоги и сообщения хранятся в БД: после обновления страницы открыт тот же чат.
2. Лента диалога — `GET /ai/conversations/:id/messages` с конца: первая страница — последние 20 сообщений, сверху кнопка «Показать раньше» подгружает более старые (`nextCursor`).
3. Сообщение → `POST /ai/conversations/:id/messages` → сервер берёт `StudentContext` (кэш 5 мин) → системный промпт `tutor.system` (актуальная версия — `packages/ai/src/prompts`) + последние 20 сообщений → GigaChat stream → SSE.
4. Сохранение `AiMessage` (user/assistant), событие `tutor.message.sent` → `ActivityEvent` (без ответа модели событие не шлётся).
5. Ошибка стрима (лимит, сеть, сбой) не теряет вопрос: «отправленный» пузырь убирается, если ответ не начался — текст возвращается в поле ввода; лента перезапрашивается. «Стоп» до первого токена не добавляет пустой ответ; частичный ответ после «Стоп» пропадает до прихода перезапрошенной ленты.
6. Лимит сообщений в сутки (день по Москве, тратится только на успешный ход) → 429 с человеческим текстом в UI.

## F5. Профиль и «Моя траектория»
1. `/student/profile` → статистика, кружки, `GET /student/trajectory`. «Моя траектория» свёрнута по умолчанию; шеврон в заголовке (`aria-expanded`) раскрывает и скрывает её, «Обновить» — в раскрытом виде.
2. Траектория генерируется worker'ом: еженедельно по cron и при ≥5 значимых событиях (сдачи/оценки) с последней генерации; `sourceHash` исключает повтор на тех же данных.
3. Ручной «Обновить» → 202, job в очередь, UI показывает «Пересчитываем» и опрашивает `GET /student/trajectory` раз в 5 с до новой `generatedAt`, но не дольше 60 с (подпись «обновится через минуту»), затем снимает статус.

## F6. Преподаватель: отметить посещаемость
1. `/teacher/assignments` → кнопка «Отметить посещаемость» → `/teacher/attendance`: занятия за 14 дней назад и 7 вперёд (`GET /teacher/calendar`), разложенные по важности — «Сегодня», «Ждут отметки» (начались, но ещё `PLANNED`), «Ближайшие». Отменённые не показываются. Занятие в состоянии `DONE` помечено «Отмечено».
2. Занятие → `/teacher/attendance/:lessonId` → `GET /teacher/lessons/:id/attendance` → зачисленные ученики с текущими статусами.
3. По умолчанию все `PRESENT` (уже проставленные отметки сохраняются), преподаватель меняет только отличия — по ученику сегментированный переключатель из 4 статусов, плюс «Все пришли» / «Никого не было». Сохранение — одним `PUT /teacher/lessons/:id/attendance` со всем листом.
4. Система: upsert `Attendance`, `Lesson→DONE`, событие `attendance.marked`. Повторный `PUT` идемпотентен: лист перезаписывается целиком. Отменённое занятие отметить нельзя (422), ученик не из группы в листе — 422.
5. Обработчики: `analytics` (день каждого ученика), `notifications` (родителю `ATTENDANCE_ABSENT`, если включено), `ai` (инвалидация).

## F7. Преподаватель: простое задание
1. `POST /teacher/assignments {publish:true}` — группа, текст, дедлайн и (необязательно) `studentIds`. Отдельного экрана у простого задания нет: с экрана заданий преподаватель идёт в мастер «Задать ДЗ» (F8), а эта ручка остаётся для заданий без учебного содержимого.
2. `notifications` → ученикам группы `ASSIGNMENT_NEW`; задание появляется в `/student/home` и у родителя в «новые задания».
3. Проверка: `GET /teacher/assignments/:id/submissions` → сдача → `POST /teacher/submissions/:id/grade` → событие `submission.graded` → уведомления ученику/родителю, аналитика.

## F8. Преподаватель: задать ДЗ / собрать курс (course builder)
Единственная точка входа — кнопка «Задать ДЗ» на `/teacher/assignments`. В настройках пункта «Конструктор курса» больше нет: и одно ДЗ, и целый курс собираются одним мастером, а ученик в обоих случаях видит курс, который просто пополняется.

1. `/teacher/assignments/new`, три шага:
   - **Кому** — группа (`GET /teacher/groups`), затем «Всей группе» (по умолчанию) или выбор учеников галочками (`GET /teacher/groups/:groupId`). Без группы и без хотя бы одного выбранного ученика дальше не пустит. Групп нет — «Создать группу» (F19); в выбранной группе нет учеников — подсказка «Добавить учеников» (к составу группы, F19).
   - Экран мастера — ровно по высоте области между шапкой и меню и сам не прокручивается: прокручивается только поле шага, «Далее»/«Назад»/«Сгенерировать» всегда видны внизу.
   - **Что** — «Одно ДЗ» (`target: HOMEWORK`, ровно один модуль) или «Целый курс» (`target: COURSE`); куда положить — «Новый курс» или существующий курс группы (`GET /teacher/courses?groupId`, архивные не предлагаются); срок сдачи и название.
   - **Материал** — «Описать словами» (тема/задание, ≥ 10 символов) или «Загрузить материалы» (pdf/docx/txt/md). Материалы png/jpg/pptx загрузить можно, но задачу с ними сервер отклоняет сразу (422 `BUSINESS_RULE`): текст из них пока не извлекается.
2. `POST /teacher/course-builder/jobs` → worker: EXTRACT → OUTLINE → GENERATE → ASSEMBLE; фронт опрашивает job, показывает этап и прогресс.
3. `READY` → уведомление `GENERATION_DONE` → экран ревью: модули/блоки, `PUT .../draft` до принятия.
4. «Принять» → `POST .../accept`:
   - `targetCourseId` задан — новые модули дописываются в конец курса, курс остаётся тем же (ученик продолжает проходить его же);
   - иначе создаётся `Course(DRAFT)`;
   - `target=HOMEWORK` (а также дополнение уже опубликованного курса) публикуется сразу: блоки-задания модуля становятся `Assignment` с `dueAt` и `studentIds` задачи. Целый новый курс остаётся `DRAFT` — его преподаватель публикует сам.
5. «Опубликовать» → дедлайны для блоков-заданий → `POST /teacher/courses/:id/publish`. Публикация идемпотентна и инкрементальна: блок, у которого задание уже есть, пропускается, поэтому курс можно дополнять сколько угодно раз.
6. Событие `course.published` → `notifications` → ученикам `COURSE_PUBLISHED`.

## F9. Родитель: привязка ребёнка и просмотр
1. Вход → роль PARENT → главная `/parent`: детей нет — в карусели «сердечек» только белый «+» → «Добавить ребёнка»: ссылка-приглашение (F14) или код из профиля ребёнка → `POST /parent/children/link`. «+» есть всегда (добавить ещё ребёнка; экран детей, выбор ребёнка в аналитике).
2. Выбор ребёнка — свайп карусели сердечек (Zustand `selectedChildId`, персистится в MAX storage) → `GET /parent/children/:id/home` (расписание как у ученика: «‹ Сегодня ›», календарь, уведомления) и `GET /parent/children/:id/homework-progress?days=1|7|30` (кружки «Выполненные задания»: чем больше сделано из рекомендованного, тем кружок меньше; формула — docs/04 §4.6).
3. Аналитика `/parent/analytics` → выбор ребёнка → `GET /parent/children/:id/analytics`: «Посещения» (дуга недели), «Домашние задачи» (правильно / неправильно / предстоят), по кружкам — полоса итогов и «Подробнее» → сетка заданий (зелёный — сделано, красный — дедлайн прошёл или < 30%, жёлтый — дедлайн ≤ 72 ч, серый — не скоро). Тап по клетке → `GET /parent/children/:id/groups/:groupId/tasks` — условия, код, ответ ребёнка и правильный ответ.
4. Переключение ребёнка → все запросы перезапрашиваются по новому `studentId` (ключи Query содержат `studentId`).
5. Статус связи: на главной (сердца), в выборе ребёнка аналитики и при авто-выборе (`ParentShell`) участвуют только дети со связью `ACTIVE`; выбранный не-ACTIVE ребёнок сбрасывается на первого ACTIVE (или ни на кого). Если детей со связью `ACTIVE` нет (только `PENDING`/`REVOKED`), экраны «про ребёнка» показывают пустое состояние «Добавить ребёнка». На экране «Дети» (`/parent/children`) у `PENDING`/`REVOKED` — бейдж статуса («Ожидает»/«Отвязан») и нет кнопки «Выбрать», у выбранного — бейдж «Выбран». Неверный код привязки — «Код не найден…» (NOT_FOUND), а не «раздел в разработке».
6. «Дети», «Кружки» и «Оплата» открываются и из настроек родителя; «Назад» на них — по истории, по прямой ссылке — на `/parent`.
7. Настройки родителя `/parent/settings`: профиль, «Семья и оплата» (дети, кошелёк, оплата, кружки), внешний вид (только тема), аккаунт (роль, поддержка), выход. Уведомлений, выбора языка и подписи о приложении у родителя нет.
8. Размеры экранов: главная `/parent` фиксирована ровно в окно — шапка и сердца стоят, кривая панели заходит под подпись выбранного сердца (как в макете), а расписание и «Выполненные задания» прокручиваются внутри панели, только если не влезли (в MAX окно ниже браузерного). Тьютор — шапка и чат ровно в высоту окна, прокручивается только длинная лента. Экраны-списки (настройки, дети, кружки, оплата, профиль, аналитика) прокручиваются по содержимому.

## F10. Родитель: оплата
1. `/parent/payments` → кружок → «Оплатить» → количество месяцев → `POST /parent/children/:id/payments` с `Idempotency-Key` (один ключ на попытку оплаты периода: повтор после сбоя — тот же ключ) → `confirmationUrl`. Спиннер — только на нажатой кнопке «Оплатить».
2. Открытие платёжной страницы через `MaxBridge.openLink`.
3. Провайдер → `POST /webhooks/payments/:provider` → подпись → `Payment(SUCCEEDED)` → `PaidPeriod` → событие `payment.succeeded` → уведомление родителю.
4. После «Оплатить» экран опрашивает `GET /parent/payments/:id` раз в 3 с, пока статус `PENDING`, но не дольше 60 с; затем показывает тост с итогом и перезапрашивает платежи ребёнка (история, «оплачено до»). Даты `paidUntil`/`nextPaymentAt` (`YYYY-MM-DD`) показываются как локальные (`formatDateOnly`), без сдвига часового пояса.

## F11. Переключение ролей
Пользователь с несколькими ролями (преподаватель, у которого свой ребёнок) — в профиле «Сменить роль» → `POST /auth/switch-role` → новый JWT → переход на `/`, дальше `RootRedirect` ведёт на корень роли (ученик без онбординга — на `/onboarding`). Добавить роль — `POST /auth/roles`. Прежний refresh-токен при смене роли не отзывается (техдолг, docs/12).

## F12. Отмена занятия
Преподаватель → `PATCH /teacher/lessons/:id {status: CANCELLED}` → событие `lesson.cancelled` → уведомления ученикам и родителям группы; занятие исключается из `countable` в посещаемости.

## F13. Родитель: пополнение кошелька (заглушка)
1. Главная родителя → кошелёк справа сверху (`GET /parent/wallet`, баланс в рублях) → `/parent/wallet`.
2. «На сколько хотите пополнить?» — сумма (100 ₽ … 100 000 ₽) или пресет 500 / 1000 / 3000 / 5000 → «Пополнить» → `POST /parent/wallet/top-up { amountKopecks }` с `Idempotency-Key`.
3. **Сейчас заглушка**: сумма зачисляется сразу, без оплаты; UI пишет «демо-режим». Ручка работает только при `PAYMENT_PROVIDER=fake` — с настоящим провайдером она отвечает 501, чтобы не печатать деньги. С реальным провайдером поток станет как F10 (`confirmationUrl` → вебхук → зачисление).

## F14. Родитель: приглашение ребёнка по ссылке
1. Родитель → «Добавить ребёнка» (главная, аналитика, тьютор) или «Дети» → «Пригласить по ссылке» → `POST /parent/children/invites` → `{ token, url, expiresAt }` (7 дней, одноразовая). `url` — диплинк мини-приложения MAX `https://max.ru/<MAX_BOT_NAME>?startapp=invite_<token>`; без `MAX_BOT_NAME` — веб-адрес `${WEB_URL}/invite/<token>` (для браузера; внутри MAX такая ссылка откроется в браузере, где входа через MAX нет).
2. «Поделиться» (`navigator.share`, иначе копирование: Clipboard API, в WebView без него — выделение поля и `execCommand('copy')`) → родитель отправляет ссылку ребёнку в MAX. Пока ссылка на экране, список детей перечитывается раз в 5 с: когда ребёнок подтвердит, родитель сразу видит тост «Ребёнок принял приглашение: …», ребёнок появляется в списке (из шторки «Добавить ребёнка» — выбирается и шторка закрывается), а ссылка сбрасывается — для следующего ребёнка создаётся новая.
3. Ребёнок открывает ссылку в MAX → мессенджер запускает мини-приложение на корневом адресе со `start_param=invite_<token>` → при старте (один раз за запуск, только со стартового корня) приложение переходит на `/invite/<token>`; вход — по подписи MAX. В браузере то же эмулирует `?startapp=invite_<token>` (mock-мост). Прямой адрес `/invite/<token>` тоже работает.
4. `/invite/:token` (после входа). Активная роль STUDENT → `GET /student/parent-invites/:token` → «{Родитель} хочет следить за твоими успехами» → «Подтвердить» → `POST /student/parent-invites/:token/accept` → связь `ParentStudentLink` `ACTIVE` (токен гасится в той же транзакции) → `/` (онбординг ученика, если не пройден, иначе `/student`).
   - Повтор тем же учеником идемпотентен, пока связь `ACTIVE`; после отвязки погашенная ссылка связь не восстанавливает (`BUSINESS_RULE`), нужна новая.
   - Ребёнок уже привязан к этому родителю: `GET` отдаёт `alreadyLinked: true`, экран сразу показывает «Ты уже привязан к этому родителю» без «Подтвердить»; `accept` в этом случае — 409 `CONFLICT`, ссылка не гасится (её можно отправить другому ребёнку).
   - Ссылку уже принял другой ученик — 409 `CONFLICT`, экран «Приглашение уже принято»; одновременное принятие двумя учениками привязывает ровно одного.
   - Истёкшая — «Срок действия ссылки истёк» (`accept` — 422 `BUSINESS_RULE`); неизвестный токен — «Приглашение не найдено» (404); свой же аккаунт (роли родителя и ученика у одного пользователя) — 422.
   - Не ученик — подсказка открыть ссылку из аккаунта ребёнка (или сменить роль); новый пользователь без ролей — «Я ученик» прямо на экране приглашения.
5. Ребёнок появляется у родителя в `GET /parent/children`, в карусели сердец и в аналитике; данные ребёнка родителю открыты (policy `assertParentLinked`).

## F15. Родитель: ИИ-тьютор о ребёнке
1. `/parent/tutor` → чат про выбранного ребёнка: `GET /parent/children/:id/ai/conversations` → последний диалог или `POST .../ai/conversations`; история — `GET /parent/ai/conversations/:id/messages` с конца, как у ученика (последние 20, сверху «Показать раньше»).
2. Сообщение → `POST /parent/ai/conversations/:id/messages` (SSE) → сервер проверяет связь родитель ↔ ребёнок (`FamilyService`, иначе 403), берёт `StudentContext` ребёнка → промпт `tutor.parent` → стрим. Ошибка стрима и «Стоп» — как у ученика (F4 п. 5): вопрос не теряется, ошибка видна до следующей отправки.
3. ИИ говорит **с родителем** (на «вы») о том, как занимается ребёнок: посещения, выполнение и просрочки заданий, прогресс по кружкам, где нужна помощь, как поддержать; без выдуманных фактов. Лимит сообщений — как у ученика (429).

## F16. Преподаватель: главная и расписание
1. Вход → роль TEACHER → главная `/teacher` (оранжевый акцент): аватар и имя, чип кошелька (`GET /teacher/wallet`, баланс целыми рублями, без «+») → F17, иллюстрация, «‹ Сегодня ›» с таблицей «Название | Группа | Время» из `GET /teacher/home` (`today` + `upcoming`). В колонке «Группа» — `group.code`, иначе `title`; текущее занятие подсвечено.
2. Дни вне окна главной и шторка календаря (месяц, точки на днях с занятиями) → `GET /teacher/calendar?from&to` (занятия всех групп преподавателя). Колокольчик — уведомления, как у ученика (F2).
3. Нижнее меню: главная · задания (`/teacher/assignments`, F7) · «Успеваемость» (центральная кнопка, F18) · настройки · профиль. Настройки `/teacher/settings`: профиль; «Работа» — кошелёк, группы (F19), курсы, конструктор курса (F8), спрос на кружки; внешний вид (только тема), смена роли (F11) и поддержка, выход. Уведомлений, языка и подписи о приложении у преподавателя нет. Старый `/teacher/more` → редирект на `/teacher/settings`. Экраны «Работы» подсвечивают в меню «Настройки»; «Назад» со списков групп и курсов, из конструктора курса и со «Спроса на кружки» ведёт в `/teacher/settings` (не `navigate(-1)` — работает и по прямой ссылке); с курса — в список курсов, с задачи генерации — в конструктор. Чужая группа (403) — «Группа не найдена» без «Повторить».
4. Профиль `/teacher/profile`: фото (сменить его пока нельзя — `PUT /me/avatar` = 501, docs/12), «Преподаватель · N групп · M учеников», «Мои группы» (→ `/teacher/groups/:id`; «назад» с карточки группы возвращает туда, откуда её открыли — в профиль или список групп), плитки статистики из `GET /teacher/home`.

## F17. Преподаватель: кошелёк и вывод (заглушка)
1. Чип кошелька на главной или «Настройки → Кошелёк» → `/teacher/wallet` → `GET /teacher/wallet?period=day|week|month` (1 / 7 / 30 дней, по умолчанию день): баланс, график «Изменение баланса» (`history`), «Транзакции» по дням («сегодня», «вчера», дата; поступления зелёные, вывод — красная строка «Вывод»), «Вам должны» (группа, ученик, сумма, дата следующего платежа; просроченная — красная). Смена периода перезапрашивает кошелёк.
2. «Вывести» → шторка: сумма (100 ₽ … баланс) или 1000 / 3000 / 5000 / «Всё» → `POST /teacher/wallet/withdraw { amountKopecks }` с `Idempotency-Key` (один на попытку: повтор той же суммы после сбоя — с тем же ключом, новая сумма или новое открытие шторки — новый; пока запрос идёт, шторку не закрыть) → новый баланс и операция вывода, тост «демо-режим»; кошелёк перезапрашивается после любого исхода (при таймауте виден фактический баланс).
3. Ошибки: больше баланса → 422 `BUSINESS_RULE` («Недостаточно средств»), меньше минимума → 400 `VALIDATION`, тот же ключ с другой суммой → 409 `CONFLICT`. Повтор с тем же ключом и суммой не списывает второй раз.
4. «Баланс ✕»: открыт из приложения — назад, по прямой ссылке — на `/teacher`.
5. **Поступления настоящие**: оплата родителя по `payment.succeeded` создаёт операцию `INCOME` в кошельке преподавателя группы (пока на всю сумму — доли школы в модели данных нет). Заглушкой остаётся вывод: сумма списывается с баланса, но никуда не уходит, поэтому ручка работает только при `PAYMENT_PROVIDER=fake`, иначе 501. С провайдером вывод станет выплатой со статусом (модель — docs/04, payments).

## F18. Преподаватель: успеваемость групп → ученик → задания
1. Меню «Успеваемость» → `/teacher/performance` → `GET /teacher/performance?period=day|week|month|course` (1 день / 7 дней / 30 дней / 1 курс, по умолчанию день, выбор хранится в `?period=`; формулы — docs/04 §4.6): «Посещения» — столбец на группу (снизу посетили, сверху пропустили; цвет — по кружку, легенда слева, подпись — код группы) и таблица «Группа | Правильно выполненные дз | Выполненные дз». Групп нет — пустое состояние.
2. Строка таблицы → `/teacher/performance/groups/:groupId` → `GET /teacher/groups/:groupId` → ученики группы (посещаемость, прогресс); «назад» — к общей успеваемости с тем же периодом (открыто из приложения — назад по истории, по прямой ссылке — на `/teacher/performance`); чужая группа — «Группа не найдена».
3. Ученик → `/teacher/students/:studentId` → `GET /teacher/students/:studentId` (только общие группы; нет общих — 403 → «Ученик не в ваших группах»): «Посещения» (дуга недели `week`), «Домашние задачи» (`homework`), по кружкам — полоса итогов и «Подробнее» (`?club=<groupId>`) → сетка заданий (цвета и порог 30% — как у родителя, F9 п. 3).
4. Тап по клетке → `/teacher/students/:studentId/groups/:groupId/tasks?task=<assignmentId>` → `GET /teacher/students/:studentId/groups/:groupId/tasks` — условия, код, ответ ученика и правильный ответ; экран прокручивается к выбранному заданию.
5. «Успеваемость ✕» / «Задания ✕»: открыт из приложения — назад, по прямой ссылке — на уровень выше с заменой истории (`/teacher/performance`, `/teacher/students/:id?club=<groupId>`).

## F19. Преподаватель: группы — создание, название, состав
1. «Настройки → Группы» → `/teacher/groups` → «Создать группу» → `/teacher/groups/new`: название и кружок школы (`GET /catalog/clubs`, по умолчанию первый) → `POST /teacher/groups` → экран состава новой группы (создание заменяется им в истории).
2. Карточка группы `/teacher/groups/:id` → «Изменить» у учеников (у пустой группы — «Добавить учеников») → `/teacher/groups/:id/edit`: название (`PATCH /teacher/groups/:id`, кнопка «Сохранить название» — только при изменении), ученики группы с «убрать» (`DELETE /teacher/groups/:id/students/:studentId`), «Добавить учеников» — поиск по имени (`GET /teacher/groups/:id/candidates?q`: ученики школы преподавателя и его других групп) и «добавить» (`POST /teacher/groups/:id/students`). Всё сохраняется сразу; после каждого изменения данные преподавателя (главная, списки, успеваемость, мастер ДЗ) перезапрашиваются.
3. Новая группа сразу доступна в мастере «Задать ДЗ» (F8) и в простом задании (F7); ДЗ «всей группе» видят и ученики, добавленные позже. Убранный ученик остаётся в истории (зачисление `LEFT`), адресатом ДЗ группы его выбрать нельзя.
4. Чужая группа (403) — «Группа не найдена» с возвратом к списку групп.
