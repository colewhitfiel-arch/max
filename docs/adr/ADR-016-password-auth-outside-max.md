# ADR-016. Регистрация и вход по логину и паролю вне MAX

Дата: 2026-09-30. Статус: принят. Дополняет ADR-006 (вход через MAX → собственный JWT).

## Контекст

Внутри MAX личность подтверждает подпись launch-параметров, аккаунт создаётся при первом входе.
В обычном браузере (стенд, проверка жюри, тестирование) войти можно было только демо-аккаунтами
(`POST /auth/dev`), а на стенде с `AUTH_PROVIDER=max` — только ими: произвольный `maxUserId`
там был бы входом в чужой аккаунт MAX. Пройти сценарий «с нуля» — новый преподаватель, его
группа, новый ученик по ссылке, курс из конспекта — было нельзя: все демо-аккаунты общие и уже
наполнены данными. Кроме того, стенд из РФ открывается в MAX не у всех (docs/12).

## Решение

1. Два публичных роута в `authContract`: `POST /auth/register { login, password, firstName,
   lastName? }` и `POST /auth/login { login, password }` → тот же `AuthResult`, что у входа через
   MAX. Лимит частоты — общий `auth` (с одного IP).
2. Учётные данные — таблица `user_credentials` (`userId` PK/FK, `login` unique, `passwordHash`).
   Пароль хэшируется `scrypt` из `node:crypto` (без нативных зависимостей), параметры хранятся
   в строке хэша. Проверка за постоянное время; неизвестный логин проверяется по фиктивному хэшу,
   ответ на любую ошибку один — 401 «Неверный логин или пароль».
3. У аккаунта из регистрации `maxUserId = web:<uuid>`: с пользователями MAX он не пересекается —
   это отдельный аккаунт, а не второй способ войти в аккаунт MAX (привязка — отдельная задача).
4. Новый аккаунт создаётся без ролей: дальше обычный сценарий выбора роли и онбординга.
5. Вне production преподаватель без кода школы попадает в демо-школу — новый аккаунт проходит
   весь сценарий без администратора школы. В production код обязателен, как раньше.
6. Внутри MAX экран входа не меняется: автовход по подписи. Вкладки «Вход / Регистрация / Демо»
   показываются только в браузере.

## Последствия

- Стенд и Docker-сборку можно проверить «с нуля» в браузере; полный сценарий покрыт
  интеграционным тестом `apps/api/test/integration/full-scenario.test.ts`.
- Восстановления пароля нет (нет почты/телефона) — забытый пароль означает новый аккаунт.
- Регистрация доступна и в production; если это нежелательно, её отключает отдельный флаг env
  (не заведён — решение за владельцем api-shell).
