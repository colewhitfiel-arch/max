# ADR-011. UI-слой на обычном CSS с токенами вместо Tailwind (уточняет ADR-005)

**Статус:** accepted, 2026-09-21

## Контекст
ADR-005 предполагал Tailwind 4. На этапе foundation зафиксировано требование: визуальный дизайн временный и позже должен быть заменён целиком, преимущественно внутри UI-слоя, без переписывания бизнес-логики и экранов.

Tailwind размазывает визуальные решения по разметке каждого экрана (utility-классы в JSX фич). Полная смена дизайна означала бы правку всех фич.

## Решение
- `packages/ui` — единственное место визуальных решений: `tokens.css` (CSS custom properties: цвета, типографика, отступы, радиусы, тени, z-index, анимации) + один `.css` на компонент. Классы `ui-*`, варианты через `data-*` атрибуты.
- Компоненты имеют стабильный API (props, состояния, варианты, a11y), их внешний вид меняется правкой CSS/токенов.
- Фичи и страницы не пишут визуальных стилей: только композиция компонентов и layout-примитивов (`Stack`, `Inline`, `Screen`, `AppLayout`). Локальные стили допустимы только для раскладки, через CSS-модули в зоне фичи.
- Tailwind не используется; при необходимости его можно добавить позже только внутри `packages/ui`.

## Последствия
- Смена дизайна = замена `tokens.css` и CSS компонентов, плюс, при необходимости, внутренней разметки компонентов. Потребители не меняются.
- Нет зависимости сборки на PostCSS/Tailwind-плагины.
- Дизайнеру/агенту дизайна выдаётся одна зона — `packages/ui`.
