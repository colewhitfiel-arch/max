# ADR-002. Модульный монолит NestJS + отдельный worker-процесс

**Статус:** accepted, 2026-09-21

## Контекст
15 доменных модулей, сильно связанных через ученика. Микросервисы на старте дадут сетевые границы там, где нужны транзакции и простые join'ы. При этом ИИ-пайплайны и пересчёты долгие и не должны жить в HTTP-запросе.

## Решение
Один Nest-проект `apps/api`, два entrypoint'а: `main.ts` (HTTP) и `worker.ts` (BullMQ-процессоры). Те же модули, разные точки входа; деплой — два контейнера.

Изоляция модулей — организационная и проверяемая: модуль читает только свои таблицы, чужое — через публичный сервис или события (`08-dependencies.md`). Это делает выделение модуля в сервис механической операцией.

## Последствия
- Транзакции внутри модуля, консистентность между модулями — eventual через события.
- Один деплой-артефакт для api и worker; масштабируются независимо.
- Первый кандидат на выделение — `course-builder` (тяжёлый, бурстовый).
