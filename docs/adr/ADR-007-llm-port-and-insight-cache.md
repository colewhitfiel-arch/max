# ADR-007. LLM за портом, промпты в репо, инсайты через кэш worker'ом

**Статус:** accepted, 2026-09-21

## Контекст
GigaChat используется в девяти сценариях (онбординг, тьютор, три вида резюме, траектория, три этапа course builder). Вызовы дорогие и медленные; часть ответов должна быть структурированной; данные детей нельзя отдавать модели целиком.

## Решение
- Интерфейс `LlmProvider { chat, stream, embed }` в `packages/ai`; адаптеры `GigaChatProvider` и `FakeLlmProvider`. Фичи не знают о провайдере.
- Промпты — код в репо с версией (`id@version`) и zod-схемой ожидаемого ответа; версия пишется в результат (`AiInsight.promptId` и т.д.).
- Модель получает `StudentContext` — сжатый снимок (≤2500 токенов), собранный `context-builder` из публичных сервисов; PII минимизирована.
- **Синхронно** (SSE в запросе) — только чат тьютора и онбординг. Всё остальное (инсайты, траектория, course builder) — worker'ом, результат кэшируется в БД (`AiInsight`, `Trajectory`, `CourseGenerationJob.draft`); ручка отдаёт кэш или `null`.
- Инвалидация — по доменным событиям с дебаунсом; `sourceHash` предотвращает повторную генерацию на тех же данных.
- Структурированные ответы валидируются zod, до 2 ретраев с текстом ошибки.

## Последствия
- Главные экраны не ждут модель; ИИ-поля появляются асинхронно.
- Расход токенов контролируем: лимиты на пользователя, метрики по `promptId`.
- Смена модели/провайдера — правка адаптера и, возможно, версий промптов.
