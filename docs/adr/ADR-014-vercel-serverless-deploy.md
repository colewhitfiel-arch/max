# ADR-014. Боевой стенд на Vercel: статика + одна serverless-функция с NestJS

Дата: 2026-09-27. Статус: принят. Дополняет ADR-012 (dev без Docker) и `compose.yaml` (Docker-сдача).

## Контекст

Мини-приложение MAX должно быть доступно по постоянному https-адресу на момент проверки жюри
(критерий допуска), при этом у команды нет сервера, а Docker-конфигурация обязана остаться
в репозитории как воспроизводимая сборка. Выбрана площадка Vercel (тариф Hobby).

Ограничения площадки, которые определили решение:

- функция живёт до 300 с (Hobby, Fluid compute включён по умолчанию); инстанс замораживается
  сразу после ответа, если его не удержать;
- файловая система только для чтения (кроме `/tmp`), память процесса не разделяется между
  инстансами;
- тело запроса к функции ограничено (~4,5 МБ);
- дата-центры вне РФ — доступность GigaChat проверена зондом: OAuth на порту 9443
  с сертификатом НУЦ отвечает из `iad1` за ~400 мс.

## Решение

1. **Один проект = один origin.** Статика `apps/web/dist` + функция `api/index.js`, в которую
   `vercel.json` переписывает весь `/api/*`; остальное — SPA-fallback на `index.html`.
   Требование MAX «мини-приложение на одном origin» выполняется без nginx.
2. **NestJS внутри функции** — `apps/api/src/vercel.ts`: приложение поднимается один раз на
   инстанс через `ExpressAdapter`, дальше переиспользуется. `main.ts`/`worker.ts` не меняются.
3. **Очередь остаётся inline**, но `InlineJobQueue` получает хук `keepAlive`, в который
   `vercel.ts` передаёт `waitUntil` из `@vercel/functions`: платформа не замораживает инстанс,
   пока фоновая задача (пайплайн course-builder) не завершится — в пределах `maxDuration: 300`.
4. **KV — в Postgres** (`KV_DRIVER=postgres`, таблица `kv_entries`): идемпотентность, дневные
   лимиты тьютора и кэш контекста должны быть общими для всех инстансов. `memory` остаётся
   для dev и тестов.
5. **Файлы — S3-совместимое хранилище по presigned URL** (`S3Storage` реализован поверх
   `@aws-sdk/client-s3`): байты не идут через функцию, лимит тела запроса не мешает.
6. **Сертификат НУЦ Минцифры** передаётся в env как base64 (`GIGACHAT_CA_CERT_B64`);
   `vercel.ts` записывает его в `/tmp` и подставляет путь. Файл в репозитории не хранится.
7. **Миграции и seed — на этапе сборки** (`scripts/vercel-build.mjs`): `prisma migrate deploy`
   через непулированное подключение, seed по флагу `SEED_ON_DEPLOY=1`.
8. **`APP_ENV=staging`**, а не `production`: production-guard требует настоящий провайдер
   оплаты, которого у MVP нет. Dev-вход в браузере при этом остаётся, вход по подписи
   внутри MAX — основной (`VITE_AUTH_MODE=auto`).

## Последствия

- Docker-путь (`Dockerfile`, `compose.yaml`, nginx) не меняется и остаётся эталоном для сдачи;
  Vercel — только площадка живого стенда.
- Холодный старт функции — секунды (поднятие Nest + Prisma); первый запрос после простоя
  медленнее.
- Пайплайн course-builder обязан укладываться в 300 с; при персональном тарифе GigaChat
  (`GIGACHAT_MAX_CONCURRENCY=1`) запросы идут последовательно — для больших материалов
  потребуется разбиение по стадиям (состояние стадий уже хранится в `CourseGenerationJob`).
- Тариф Hobby не допускает коммерческое использование — для пилота с деньгами нужен Pro
  или российский хост.
- `bullmq`-режим и `worker.ts` на Vercel не используются.
