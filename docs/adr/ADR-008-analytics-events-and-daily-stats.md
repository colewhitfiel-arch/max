# ADR-008. Аналитика: события + дневные агрегаты, формулы в одном модуле

**Статус:** accepted, 2026-09-21

## Контекст
Одни и те же показатели (посещаемость, выполнение, активность, прогресс) показываются ученику, родителю, преподавателю и подаются в ИИ. Если каждый экран считает их сам — цифры разойдутся. Дашборды должны отвечать быстро на мобильном.

## Решение
- Все формулы (`04-data-model.md` §4.6) живут только в `modules/analytics`. Другие модули не считают проценты.
- Источник — фактические таблицы (`Attendance`, `Submission`, `BlockProgress`) + лента `ActivityEvent`. Модули публикуют события, `analytics` подписан на все.
- Read-model `StudentStatsDaily` пересчитывается worker'ом по событиям (дебаунс 1 мин на ученика) и полностью ночью. Динамика по неделям — из него; текущие 30 дней — из него же с досчётом сегодняшнего дня.
- Агрегирующие ручки дашбордов (`/student/home`, `/parent/.../home`, `/teacher/home`, ...) — в `analytics/dashboards`: один запрос → один DTO.

## Последствия
- Единые цифры у всех ролей и у ИИ.
- Eventual consistency: после отметки посещаемости родитель увидит новое значение через секунды, не мгновенно (допустимо).
- `analytics` зависит от всех учебных модулей — это осознанно, он на верхнем слое.
