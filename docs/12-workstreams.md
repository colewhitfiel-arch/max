# 12. Workstreams после foundation

Foundation завершён (`docs/FOUNDATION.md`). Ниже — независимые направления для параллельных агентов. Перед стартом каждый читает `docs/AGENT_GUIDE.md`. Общие правила для всех workstream'ов:

- **Контракт** для домена уже описан в `packages/contracts/src/routes/<domain>.ts` — реализуй его; менять формы можно только добавлением полей (иначе координация с владельцем contracts и FE-потребителями).
- **Не трогать:** `apps/api/src/common/**`, `apps/api/src/app.module.ts`, `apps/web/src/app/**`, `apps/web/src/shared/**` (кроме своих `shared/api/mocks/handlers/<domain>.ts` и `shared/i18n/<ns>.*.json`, см. `10-ownership.md` §10.5), `packages/db/prisma/schema/migrations/**`, `packages/db/prisma/schema/base.prisma`, `packages/contracts/src/{index,enums,errors,events,permissions}.ts`, `packages/ui/**`, корневые конфиги. Нужна правка там — запрос владельцу (одна строка в `modules/index.ts`, `router.tsx`, `bottom-nav.config.ts`, `handlers/index.ts` — норма).
- **Можно использовать:** `AiService` (DI), `STORAGE`, `JOB_QUEUE`, `KV_STORE`, `DomainEventBus`, `PrismaService`, `Errors`, `@CurrentUser/@Roles/@RequirePermission`, публичные сервисы `IdentityService`, `SchoolService`, `FamilyService`; во фронте — `api`, `unwrap`, хуки `shared/auth`, `useMaxBridge`, компоненты `@edu/ui`.
- **Критерий завершения (общий):** контракт домена реализован (нереализованные ручки отдают `Errors.notImplemented`, а не 404); интеграционные тесты на ручки и policies (403 на чужой ресурс); экраны работают на настоящем api; `pnpm lint && pnpm typecheck && pnpm test && pnpm build` зелёные; `docs/04`/`docs/05` обновлены при изменениях; seed-фрагмент добавлен, если нужны данные.

### Ревью 2026-09-23

Полное код-ревью и три раунда исправлений (web-shell/student/parent/teacher/common → mocks/ui/api/ai/infra → db/ui/contracts/web/i18n/docs). Продуктовая логика не менялась; изменения поведения отражены в FOUNDATION §3, docs/04–08.

Что сделано (кратко):
- **web:** `errorElement` роутов; гейт онбординга на любом `/student/*`, `/onboarding` только для STUDENT; сессия не рвётся от сети/5xx при refresh, SSE обновляет токен, logout отзывает ротированный refresh; активный пункт меню (`exact`); «раздел в разработке» только для `NOT_IMPLEMENTED`; лента тьютора с конца («Показать раньше»), ошибка стрима не теряет вопрос; у родителя только ACTIVE дети, опрос платежа, CONFLICT приглашения; `Idempotency-Key` на попытку (оплата, сдача, вывод); даты `YYYY-MM-DD` без сдвига пояса; тексты и подписи enum — из i18n (ru = en по ключам), обращение: ученик — «ты», родитель и преподаватель — «вы»; удалены неиспользуемые виджеты и `ChildSwitcher`.
- **mocks:** ad-hoc пользователи переживают reload; постраничные уведомления и сообщения ИИ; идемпотентные сдача и платёж; статистика кружков по группе; `markedAt` посещаемости = начало занятия.
- **ui:** контраст текста (AA) в темах, переводимые aria-подписи, `Text preserveLines`, `Chip` без `aria-pressed` у кнопок, `ListRow` не нажимается клавишами из вложенных контролов, `loading` → `aria-disabled`, `CardColumns` на 375px.
- **api/ai:** атомарная ротация refresh, дедуп BullMQ только пока job активен, лимит тьютора по московскому дню и только за успешный ход, watchdog зависших генераций, безопасная отдача локальных файлов, формулы аналитики — в `modules/analytics/metrics.ts`; таймауты `@edu/ai` покрывают чтение тела, обрезанный JSON отклоняется, текст модели не попадает в логи; промпты подняты до `tutor.system@3`, `onboarding.turn@3`, `trajectory.build@3` (`tutor.parent@1`).
- **contracts/db:** ученик не получает ответы QUIZ/QUESTION (`toStudentBlock`), VIDEO только http(s), `endsAt > startsAt`, `Idempotency-Key` обязателен, пустая сдача — 400, IANA-пояс школы, фикстуры с датами от «сейчас» (`materialize*`); индексы на FK (`20260923081801_fk_indexes`), seed пересчитывает прогресс.
- **infra:** одна папка миграций, `ownership:check` по коммитам; в `OWNERS.yaml` у каждого файла репозитория есть владелец (бесхозные распределены: `modules/{school,health}`, `routes/{auth,health}.ts`, `identity/school.prisma` — api-shell; служебные страницы, вход, `shared/{store,ui}`, общие словари и конфиги `apps/web` — web-shell; словари фич — владельцам фич; `contracts/entities/**` — contracts, `entities/course.ts` — B; конфиги пакетов — владельцам пакетов, корневые — core; docs/10).

**Техдолг и открытые вопросы** (решение — за указанным владельцем):
- Архитектура (api-shell, C): `identity → family` (`countChildren` для `/me`, docs/08 §8.1); `StudentContextBuilder` и `AiRepository.futureInterestsOfSchool` читают чужие таблицы до публикации read-методов identity/groups/courses/assignments/attendance; второй парсер env в `@edu/ai` (`AiEnvSchema`) рядом с `apps/api/src/config/env.ts`; дубли `byPrompt`/`lastUser` в 5 файлах промптов.
- Auth (api-shell, db): `PUT /me/avatar` = 501 — нужен `User.avatarFileId` (docs/04), вход перезаписывает `avatarUrl` из MAX; до реализации кнопки смены фото в профилях родителя и преподавателя скрыты (`features/change-avatar` не выводится, иначе фото загружалось бы в хранилище без владельца и заканчивалось ошибкой); при `switchRole`/`addRole` прежний refresh-токен не отзывается (нужно поле в контракте или отзыв всех токенов — решение продукта); в MSW logout не отзывает refresh.
- Уведомления (L, db): экрана настроек уведомлений больше нет ни у одной роли, а `notifications` по-прежнему фильтрует доставку по сохранённым переключателям — выключенную раньше категорию не включить; решить: игнорировать сохранённые настройки или сбросить их разовой миграцией данных.
- Тьютор (C): дневной лимит считается в фиксированном поясе Europe/Moscow, а не в поясе школы (нужен `schoolId` в `TutorTurn`); проверка (`kv.get`) и учёт (`kv.incr`) лимита неатомарны — параллельные запросы могут чуть превысить лимит (нужен `decr` в порте `KeyValueStore`); ручной refresh траектории ставит job без `force` — на неизменённых данных `generatedAt` не меняется и UI через 60 с просто снимает «Пересчитываем»; частичный ответ после «Стоп» пропадает до перезапроса ленты; `TutorChat` и `ParentTutorChat` почти дублируют друг друга (кандидат на общий `useTutorChat`).
- Онбординг (C, contracts): кружки, выбранные кнопкой в онбординге (`done.clubOptions`), живут только в клиенте — после обновления страницы они не отмечены «Записаться» и могут пропасть из подборки (docs/07 F1 п. 4). Нужно хранить `pickedClubIds` в снапшоте онбординга, когда ответ совпадает с названием предложенного кружка, отдавать `pickedClubs` из `/student/onboarding/start` (опциональное поле в `OnboardingStartResultSchema`) и заполнять из него `pickedClubs` в `startConversation` (`OnboardingPage`).
- Генерация (G, ai): `chatJson` отклоняет обрезанный по `max_tokens` ответ — при `maxTokens` 4000 у урока/конспекта генерация может падать с `INVALID_RESPONSE`, стоит пересмотреть лимит.
- Контракты и DTO (contracts, A, B): `schedulePreview` (`ClubCard`) и `needsAttention` (`GroupDetail`, ученик) приходят готовыми русскими строками — нужна структурная форма (правила расписания, enum причин) с текстами через i18n; `WEEK_DAY_STATUSES` без нейтрального статуса для прошедшего дня с неотмеченными занятиями (сейчас `NO_LESSONS`); ответы INTERACTIVE (FILL_GAPS, MATCHING, FLASHCARDS) уходят ученику — решить, проверять ли их на сервере; `*_LABELS` и `BLOCK_TYPE_META[].label` веб больше не использует — удалить или пометить; `DELETE /teacher/assignments/:id` в контракте мягкое, а MSW удаляет жёстко вместе со сдачами.
- Курсы и задания (B): QUIZ-блок не закрывает связанное задание (экраны «Курс» и «Задания» не синхронизированы; после решения — инвалидация `assignments` в `useCompleteBlock`); правила `COMPLETED` при балле ниже `passScore` нет; HOMEWORK с `submissionType: 'NONE'` — как ученику отметить выполнение, если пустую сдачу контракт не принимает; доступ преподавателя к файлам сдачи через `GET /files/:id` — когда появится UI; `/student/courses` достижим только через «Открыть в курсе» — точка входа в навигации — решение продукта.
- БД (db): без индекса FK `Attendance.markedById`, `Submission.gradedById`, `CourseGenerationJob.groupId`, `AiInsight.studentId` (docs/04 §4.2.1) — добавить с первой выборкой по ним.
- Дизайн (дизайнер, ui): микротекст 7–8.4px в графиках, `CardColumns` и `CodeBlock` (кандидат — токен `--ui-font-size-2xs` 10px); белая иконка на тёмном зелёном акценте ≈2.1:1 (< 3:1); рамка danger у `Input`/`Checkbox` ≈3:1; светлой зелёной темы в макете нет; «Программирование» у родителя на 375px переносится по слогам (нужно уменьшить заголовки/время или разрешить перенос времени); ширины в `CardColumns` считались без кернинга — проверить в реальном WebView; container queries — Chrome 105+/Safari 16+, на старых WebView поля остаются 8px.
- a11y (ui): строки `CardColumns` связаны через `aria-owns` — в VoiceOver/Safari поддержка частичная (полноценно — через DOM/subgrid); `ListRow` с `role=button` содержит интерактивные элементы — нужен отдельный API (`rowProps`/`actionLabel`).
- Фейковый сервер тестов (web-shell): живёт в `apps/web/src/test/fake-api`, в приложение не попадает. Query каталога и статуса заданий не валидируются, `limit` не применяется, списки отдают всё одной страницей — расходится с настоящим api; выдуманные данные (`homework.ts`, `world-extras.ts`, `teacher-wallet.ts`) стоит заменить фикстурами, раз все ручки есть в api.
- Фронт (web-shell, владельцы фич): неиспользуемые публичные экспорты — `useDeleteConversation`, `useStudentAssignments`, `useCreateAssignment`, `useAssignmentSubmissions`, `useCatalogClubs`, `useCatalogClub`, `useHealth`, `useUploadFile`, `useUpdateGenerationDraft`, `useUpdateLesson`, `useRotateLinkCode`, `useUnlinkChild`, `useHasPermission`, `useCapabilities`, `SWITCH_ROLE_PATH`, `useMaxTheme`, `authHeaders`, типы `ApiClient`, `QueryKeyPrefix`, `AppConfig` (`useSubmitAssignment`, `RequirePermission`, `Can` — только в тестах); плюрализация без `count`: student.ru `courses.blocks` («из 1 блоков»), teacher.en `counts` («1 modules»); `/auth/switch` без «Добавить роль» — решение продукта; лишний `stopPropagation` у «Выбрать» в `ChildrenPage`.
- API-тексты (api): серверные сообщения для родителя и преподавателя проверить на обращение «вы».
- Инфра (core): `pnpm format:check` не в CI; `@edu/config` в корневых devDependencies; `scripts/**` в ignores eslint пакета db; по правилу «при равной конкретности — зона ниже» `apps/web/src/shared/max/**` принадлежит ws-J, а не web-shell.
- Вручную (разработчик, один раз): убрать `NODE_ENV=development` из локального `.env` (иначе `vite build` собирает dev-бандл), удалить старый `.data/pg.pw`, выполнить `pnpm db:deploy` (в dev-базе должны быть применены все миграции, включая `20260923081801_fk_indexes`).
